# 松间叩仙管理台设计 V3：运营工作台

> 状态：第二次反思后的修订版，尚未进入开发

## 1. 核心工作流

### 1.1 玩家投诉处理

1. 搜索玩家并打开详情。
2. 顶部显示账号状态、角色状态和健康检查警告。
3. 时间线按时间合并聊天、战斗、游历、拍卖、邮件、突破与管理员操作。
4. 从时间线证据直接发起隐藏消息、撤拍、封禁、补偿。
5. 操作完成后时间线立即新增审计事件。

### 1.2 资产异常处理

1. 查看资源流水和当前余额。
2. 选择异常流水，填写纠错原因。
3. 管理台计算调整后余额并阻止负数。
4. 服务端事务执行，写资源流水和管理员审计。

### 1.3 内容平衡调整

1. 选择内容，查看当前值、引用数量、相关区域和玩家持有量。
2. 修改字段后本地基础校验。
3. 服务端执行完整校验和影响分析。
4. 显示差异和影响摘要，确认后发布。
5. 审计保留回滚快照。

## 2. 玩家 360 视图

固定摘要：

- 玩家 ID、账号、角色、境界、在线时间、封禁状态。
- 气血、攻击、防御、身法、灵气速度、主修功法。
- 灵气、灵石、精力、奇缘、闭关和待处理遭遇。
- 健康检查：境界与倍率不一致、当前气血超界、装备门槛违规、负库存、过期状态、异常队列、拍卖资产冲突。

标签页：

- 概览与时间线。
- 行囊与资源流水。
- 功法、丹谱、炼器谱、称号。
- 装备与装备状态。
- 邮件与拍卖。
- 社交与聊天。
- 战斗、游历、突破记录。
- 管理操作记录。

右侧处置栏：封禁、踢下线、恢复状态、调整资源、发补偿、资产纠错。

## 3. 资源流水

新增 `resource_ledger`：

- characterId、resourceType、resourceId、delta、balanceAfter。
- sourceType、sourceId、description。
- operatorType、operatorId、requestId、createdAt。

第一阶段新管理操作全部写流水。现有游戏行为逐步接入；未接入前界面明确标记“历史流水不完整”，不伪装成全量经济审计。

## 4. 健康检查与修复

服务端健康检查返回问题 code、严重级别、说明、是否可自动修复：

- `HP_OUT_OF_RANGE`
- `REALM_MULTIPLIER_MISMATCH`
- `INVALID_EQUIPMENT_REQUIREMENT`
- `NEGATIVE_OR_ZERO_ASSET`
- `STALE_BUFF`
- `STALE_RETREAT`
- `BROKEN_CRAFT_QUEUE`
- `AUCTION_ASSET_CONFLICT`
- `PENDING_EVENT_AND_ENEMY_CONFLICT`

自动修复必须逐项选择；不提供“一键盲修复”。执行前预览变更。

## 5. 总览指标口径

- 今日活跃：`last_online_at >= 当日 00:00` 的唯一账号。
- 7 日活跃：最近 7×24 小时唯一账号。
- 新增玩家：`users.created_at` 时间范围内数量。
- 灵石存量：所有角色 `spirit_stones` 非负值之和。
- 活动拍品金额：活动拍品 `quantity * unit_price` 之和。
- 未领取邮件：未过期且 `claimed=false`。
- 战斗胜率：指定时间内 win / 全部 battle logs。

所有指标显示统计周期和更新时间。

## 6. 内容影响分析

- 功法：持有人数、主修人数、境界、事件引用。
- 物品：库存总量、持有人数、配方引用、商店引用、邮件附件引用。
- 装备：库存总量、装备人数、拍卖引用、配方引用。
- 区域：事件、敌人、材料掉落引用。
- 敌人：战斗次数、胜率、奖励引用。
- 商店：近期开关和价格变更审计。

被引用内容不允许改 code 或物理删除，只能停用或修改安全字段。

## 7. 管理端效率

- 全局搜索快捷键 `Ctrl+K`。
- 刷新 `F5`，关闭详情 `Esc`。
- 列表记住本次会话筛选、分页大小和排序。
- 支持复制玩家 ID、用户名、角色名和审计 requestId。
- 所有日期同时显示本地时间和悬停 UTC。
- 数字使用千分位，极大整数完整可复制。

## 8. 玩家视角预览

- 邮件预览复用玩家端标题、正文、附件结构。
- 公告预览提供桌面和手机宽度。
- 图片 URL 显示缩略图和加载失败状态。
- 预览只渲染纯文本，不执行 HTML。

## 9. V3 数据与 API 增量

- `resource_ledger` 表和玩家流水 API。
- `GET /api/admin/players/:id/timeline`
- `GET /api/admin/players/:id/health`
- `POST /api/admin/players/:id/repair/preview`
- `POST /api/admin/players/:id/repair/apply`
- `GET /api/admin/content/:resource/:id/impact`
- 所有响应含 `requestId`，管理端错误详情可复制。

## 10. V3 验收补充

- 单个玩家问题可在玩家详情内完成证据查看和处置。
- 资源调整同时生成流水和审计，余额一致。
- 健康检查不修改数据；修复预览与实际变更一致。
- 内容影响分析至少覆盖物品、装备、功法、区域。
- 邮件和公告预览无 HTML 注入。

## 11. V3 仍需反思

- 首个 owner 创建、密码轮换、备份恢复和部署手册尚不完整。
- 测试矩阵尚未明确，可能出现“能 build、不能放心用”。
