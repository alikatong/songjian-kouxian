# 松间叩仙管理台设计 V1：能力全景

> 状态：第一版提案，尚未进入开发
> 目标：列清“玩家侧一切管理”的边界，避免只做一个数据库编辑器。

## 1. 产品定位

管理台是 Windows 原生桌面应用，供游戏所有者和运营人员管理线上玩家、资产、进度、社交、经济与内容配置。应用发布为 x64 EXE，由本机 Visual Studio 构建。

管理台不直接连接 PostgreSQL。EXE 只访问后端 `/api/admin`，数据库密码只存在服务端环境变量中。所有写操作由服务端校验、事务执行并记录审计日志。

## 2. 用户与权限

管理员使用独立账号体系，不复用玩家账号。

角色：

- `owner`：全部权限、管理员账号管理、系统配置。
- `operator`：玩家、资产、邮件、公告、拍卖、内容管理。
- `support`：玩家查询、封禁、补偿邮件、聊天处置；不能改内容和核心数值。
- `auditor`：只读查询和审计导出。

首个 `owner` 通过服务端脚本创建，不提供默认密码。管理员登录签发短期 JWT；禁用管理员后旧令牌立即失效。

## 3. 信息架构

### 3.1 总览

- 玩家总数、今日/7 日新增、今日活跃、境界分布。
- 灵石总量、在售拍品、未领取邮件、近 24 小时战斗与游历数。
- 被封禁玩家、待处理异常、最近管理员操作。
- 后端、数据库、数据迁移版本状态。

### 3.2 玩家管理

- 按玩家 ID、用户名、角色名搜索；分页、排序、状态筛选。
- 查看账号、角色、境界、灵气、灵石、精力、属性、功法、装备、行囊、丹谱、炼器谱、邮件、好友、聊天、战斗、游历、拍卖、突破历史。
- 修改角色名、性别、头像、境界、灵气、灵石、精力、奇缘、基础与永久属性。
- 重置待处理事件、妖兽遭遇、闭关状态、增益状态和探索冷却。
- 满血、补满精力、修复角色派生属性。
- 封禁、限时封禁、解封、踢下线。
- 不提供永久删除账号；避免误操作和级联删除。

### 3.3 资产与进度

- 增减物品、装备，锁定或解锁，设置装备状态。
- 解锁或移除功法、丹谱、炼器谱、称号。
- 查看炼丹和炼器队列；完成、取消或清理异常队列。
- 所有增减操作必须填写原因；负数不能造成库存小于零。
- 高价值资产优先通过邮件发放，玩家领取后才进入背包。

### 3.4 邮件与补偿

- 单人邮件、按玩家筛选批量邮件、全服邮件。
- 附件支持一种物品或装备、数量、灵石；支持无附件公告信。
- 草稿预览、目标人数预估、发送确认、有效期。
- 发送任务展示进度，防止重复提交。

### 3.5 社交与聊天治理

- 全服和私聊查询，按玩家、时间、关键词筛选。
- 隐藏消息、恢复消息、记录处理原因。
- 查看好友关系；解除异常关系、处理恶意拉黑链路。
- 聊天内容不物理删除，保留审计证据。

### 3.6 经济与拍卖

- 查询活动、成交、撤销拍品，按玩家、物品、价格、状态筛选。
- 管理员撤拍时，资产通过邮件返还卖家。
- 查看灵石产出/消耗摘要和高额变动。
- 商店商品上下架、改价、修改境界门槛。
- 后续系统拍卖可复用此模块。

### 3.7 游戏内容

管理以下目录，均支持分页、搜索、校验、修改和启停：

- 境界、出身、区域。
- 功法、物品/丹药/材料、装备。
- 丹谱、炼器配方及来源说明。
- 随机事件、事件选项。
- 妖兽、BOSS、奖励。
- 区域材料掉落、品质权重、遭遇配置。
- 系统商店。

内容编辑使用字段表单，不允许任意 SQL。JSON 字段提供格式化编辑和结构校验。

### 3.8 公告与运营

- 创建、编辑、发布、撤回公告。
- 设置开始/结束时间、优先级、是否置顶。
- 公告由玩家端 API 返回，前端后续增加展示入口。
- 保存常用补偿模板和邮件模板。

### 3.9 审计与设置

- 查询管理员、动作、目标、时间、结果、原因、变更前后值。
- 导出 CSV。
- 配置 API 地址、请求超时和界面主题；凭据存 Windows Credential Manager。
- 查看管理台版本、服务端版本与数据库迁移版本。

## 4. 安全规则

- 管理 JWT 必须含 `adminId`、`role`、`tokenVersion`、独立 audience。
- 管理员登录限流；连续失败记录日志。
- 写接口按角色授权，不信任客户端隐藏按钮。
- 输入使用白名单字段、范围校验、参数化 SQL。
- 每次写操作记录管理员、动作、目标、原因、请求 ID、前后快照、IP、时间。
- 关键操作二次确认；批量操作展示目标数和样本。
- API 不返回密码哈希、JWT 密钥、数据库地址等秘密。

## 5. 技术方案

### 5.1 桌面端

- `.NET 10`、WPF、x64、单文件 self-contained 发布。
- 原生 `HttpClient` + `System.Text.Json`，减少第三方依赖。
- MVVM 分层：Views、ViewModels、Services、Models。
- 统一分页、筛选、加载、错误提示、确认对话框。
- 深色运营工具视觉；信息密度优先，不做营销式大卡片。

### 5.2 服务端

- Express 新增 `/api/admin/auth` 和 `/api/admin/*`。
- 新增管理员认证、角色授权、审计中间件。
- 涉及多表的玩家修改、发放、撤拍必须事务执行。
- 列表接口统一 `page`、`pageSize`、`search`、`sort`、`direction`。

### 5.3 数据库

建议新增：

- `admin_users`：管理员账号、角色、状态、令牌版本。
- `admin_audit_logs`：不可变操作审计。
- `announcements`：运营公告。
- `admin_mail_jobs`：批量邮件幂等任务。
- `user_sessions`：玩家会话版本，用于封禁和踢下线。

建议扩展：

- `users`：账号状态、封禁原因、封禁截止、会话版本。
- `chat_messages`：治理状态、处理人、处理时间、原因。

## 7. V1 验收标准

- EXE 可登录、退出、记住 API 地址，不保存明文密码。
- 可搜索玩家并查看完整聚合详情。
- 可封禁/解封、修改资源、发邮件、增减资产。
- 可治理聊天、撤销拍卖、管理公告和主要内容目录。
- 所有写操作生成审计记录，越权请求返回 403。
- 关键事务失败不留下半完成数据。
- 远程 PostgreSQL 密码不出现在 EXE 或本地配置中。

## 8. V1 未决问题

- “直接修改资产”和“邮件发放”边界仍不够清晰。
- 内容编辑范围过大，字段依赖和跨表校验尚未定义。
- 批量操作的幂等、回滚、性能策略不完整。
- 角色修复如何复用游戏公式，尚未形成单一事实源。
- 审计日志自身的防篡改策略不足。
