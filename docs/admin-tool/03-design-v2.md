# 松间叩仙管理台设计 V2：安全命令与一致性

> 状态：第一次反思后的修订版，尚未进入开发

## 1. 第一阶段交付范围

第一阶段必须完整交付：

- 独立管理员登录、角色权限、会话失效。
- 总览指标。
- 玩家分页搜索与聚合详情。
- 玩家封禁/解封、踢下线。
- 资源调节、状态清理、角色修复。
- 单人邮件与附件发放。
- 物品/装备增减、功法/丹谱/炼器谱解锁。
- 聊天查询与隐藏/恢复。
- 拍卖查询与管理员撤拍返还。
- 公告管理。
- 核心内容目录查询与受控修改。
- 完整审计查询。

批量邮件、内容版本发布、CSV 导出保留接口设计，但不以半成品 UI 混入首版。

## 2. 风险等级

### 低风险

只读查询、刷新、复制 ID。无需原因。

### 中风险

发无附件邮件、隐藏聊天、撤回公告。要求原因并显示确认对话框。

### 高风险

封禁、境界调整、资源扣除、资产删除、撤拍、带附件邮件、内容数值修改。要求：

- 明确 reason，至少 4 个字符。
- 输入玩家名或内容 code 确认。
- 请求携带 `Idempotency-Key`。
- 服务端事务和审计。

### 极高风险

批量发放、全服邮件、管理员管理、内容批量发布。首版 API 默认关闭，由环境变量单独启用。

## 3. 玩家领域命令

不开放任意角色 PATCH，改用：

- `adjust-currency`：灵石或奇缘增减，支持乐观锁。
- `set-stamina`：设置 0-999，并同步恢复时间。
- `move-realm`：移动境界，灵气钳制到目标要求，清理不合法遭遇和闭关，调用统一属性修复。
- `restore`：满血、清理临时状态、修复派生属性，可分项选择。
- `sanction`：封禁/限时封禁/解封，同时递增玩家会话版本。
- `grant-mail`：通过邮件发放物品、装备或灵石。
- `inventory-adjust`：纠错用直接增减，禁止低于零，处理装备中和拍卖中资产。
- `unlock`：解锁/移除功法、丹谱、炼器谱；正在使用的功法不可直接移除。

每条命令服务端重新读取当前状态，在事务内校验并返回新状态。

## 4. 并发与幂等

- `characters` 新增 `admin_version BIGINT DEFAULT 0`。
- 玩家详情返回 `adminVersion`；写请求携带 `expectedVersion`。
- 版本不一致返回 409，管理台提示刷新后重试。
- 高风险请求使用 `Idempotency-Key`；服务端记录请求摘要与响应。
- 事务中使用 `SELECT ... FOR UPDATE` 锁定玩家、库存或拍品。

## 5. 账号与会话

- `users.status`：`active`、`banned`。
- `users.ban_reason`、`banned_until`、`session_version`。
- 玩家登录和每次认证都检查状态与 sessionVersion。
- 封禁或“踢下线”递增 sessionVersion，使现有 JWT 立即失效。
- `admin_users` 同样使用 `active` 和 `token_version`。
- 管理令牌有效期 4 小时；桌面端仅在内存保存令牌。

## 6. 资产规则

- 常规补偿使用邮件；玩家主动领取后入账。
- 直接库存调整仅用于纠错。
- 删除装备时：装备中则拒绝；拍卖中则拒绝；锁定则要求 owner 权限。
- 扣物品时数量不足整笔失败。
- 撤拍：锁拍品、改为 `admin_cancelled`、创建返还邮件、审计，一次事务完成。
- 邮件附件只能是物品或装备之一；灵石可并存。

## 7. 内容管理

首版支持资源：`realms`、`techniques`、`items`、`equipment`、`events`、`enemies`、`areas`、`shop_goods`。

- 服务端为每类资源定义可编辑字段白名单和校验器。
- `id`、`code`、外键关系不能通过通用编辑修改。
- JSON 字段解析后再校验，拒绝字符串拼接。
- 改价、上下架立即生效；战斗、突破、配方数值修改标为高风险。
- 首版每次修改把完整前值写入审计，可由 owner 执行“按审计记录恢复”。

## 8. 审计模型

`admin_audit_logs` 字段：

- 管理员 ID、用户名快照、角色快照。
- action、targetType、targetId、reason。
- before、after、metadata JSONB。
- requestId、idempotencyKey、IP、userAgent、success、errorCode、createdAt。

密码、令牌、数据库配置永不进入快照。日志只允许插入和查询，不提供删除 API。

## 9. 桌面端交互

- 左侧固定导航：总览、玩家、邮件、聊天、拍卖、公告、内容、审计、设置。
- 顶部显示连接环境和管理员角色，避免误连生产环境。
- 玩家详情使用标签页，不把所有信息堆在单页。
- 所有长列表服务端分页；搜索 300ms 防抖。
- 写操作完成后刷新目标详情和审计摘要。
- 网络失败区分超时、401、403、409、422、500，给出可行动提示。

## 10. V2 验收补充

- 并发打开同一玩家，旧窗口修改必须收到 409。
- 重放相同幂等键不能重复发附件或扣资产。
- 封禁后旧玩家 JWT 立即失效。
- 撤拍失败时拍品和返还邮件均不改变。
- 管理员无法越权调用隐藏按钮对应 API。
- 内容非法 JSON、负价格、无效境界门槛被拒绝。

## 11. V2 仍需反思

- 首版功能仍多，桌面端是否能让日常处理足够快？
- 运营人员如何从异常现象定位到玩家操作链路？
- 资产调整缺少统一流水，单靠审计无法计算经济变化。
- 公告和邮件模板仍没有预览玩家实际看到的效果。
